# 07 · 口语实时对话 AI 整体方案（上下文工程）

> 版本 v0.1 草稿（待确认） · 2026-11-22
> 范围：SpeakTalk 自由对话升级为「有教学策略、有记忆、有教材支撑」的 AI 口语陪练

---

## 1. 现状盘点（v2 已具备的基础）

| 已有 | 说明 |
|---|---|
| Qwen3.8-Omni-Flash-Realtime | WebRTC 直连，服务端 `speak_sdp` 换 SDP，Key 不出服务端 |
| `speak_boot` | 服务端拼提示词（角色 + 历史 issues + 均分）+ 场景包（42 场景 / 305 跟读句 / 300 free 句） |
| `pet_speak` / `pet_speak_day` | 对话记录 + 90 天打卡 |
| SOE 新版 | 精准发音评分（跟读页双引擎） |
| 学习数据 | mastery / mistakes（记忆曲线）/ progress / plan 全在库内，可作为画像输入 |

**痛点**：当前自由对话是"一次性会话"——模型不知道孩子今天学了什么、过去聊过什么、卡在哪里；中文辅助全靠提示词里一句泛泛的规则。

## 2. 核心设计：四层提示词架构（Prefix-Stack）

提示词按"变化频率"分层，越稳定的越靠前——这既是教学设计，也是为缓存命中做的前缀对齐。

```
┌─ L0 固定层（~800 tok，全站不变，数月一改）
│   角色：Pip，PET 备考口语伙伴；安全红线；儿童对话守则；输出格式
├─ L1 教学法层（~1200 tok，随教材版本更新）
│   脚手架策略（§6 三档中文辅助）；纠错原则（recast 不打断）；
│   CEFR B1 目标；PET 口语四部分评分维度对照
├─ L2 学习者画像层（~600 tok，每天 0 点/首次会话前重建）
│   能力画像 + 弱项 + 今日学习内容 + 长期记忆摘要
├─ L3 场景/教材层（~800 tok，按所选话题注入）
│   PET 教材场景包：话题、目标句型、必备词汇、图片描述脚本
└─ L4 会话层（动态）
    本会话对话轮次 + 会话内即时事件（工具调用结果）
```

**关键约束**：L0–L1 是所有用户共享的同一前缀 → 百炼隐式缓存天然命中（命中部分按输入价 20% 计费）；L2–L3 是每用户/每场景的稳定前缀，在 5 分钟显式缓存窗口内多次续费/重连可命中。

## 3. 上下文工程：三条记忆线

### 3.1 当日口语学习线（强关联，2026-11-22 用户确认修订）

**修订**：当天学的单词、阅读、听力**不注入**口语提示词（口语是独立训练线）；强关联的是**当天口语板块自己的学习内容**：

```
今天跟读的包（pet_speak_day.shadow_done → 关联 pack 的 17 分类/示范句）
今天练过的场景（scenes 做到第几个、Part2/Part3 真题编号）
最近 7 天会话里高频出错的表达（issues）
今天的口语计划任务（90 天计划 phase → 推荐场景）
```

这些全部来自口语库自身（pet_speak / pet_speak_day / packs / scenes），与词汇/阅读数据零耦合。

### 3.2 长期对话记忆线（诉求 ② 的"过往的对话内容"）

**绝不把历史对话全文塞进提示词**（token 爆炸 + 隐私）。改为三级压缩存储：

| 层级 | 存储 | 更新时机 | 用途 |
|---|---|---|---|
| 会话摘要 | `pet_speak.summary`（≤150 tok） | 每次会话结束，用 qwen3.8-flash 生成 | 画像层"最近聊过什么" |
| 话题履历 | `pet_speak_profile.topics`（JSON 数组，含次数/日期） | 会话结束累加 | 避免重复话题、做话题推荐 |
| 错误档案 | `pet_speak_profile.issues`（去重聚合 + 频次） | 会话结束，LLM 归并到既有 issue | 教学法层的针对性策略 |

画像重建流水线（每天首次会话前跑一次，结果缓存）：

```
输入：pet_speak 近 7 天摘要 + topics + issues + 学习库当日数据
产出：L2 画像 JSON（strengths / weaknesses / today_focus / suggested_topics）
缓存：pet_speak_profile，当天 0 点失效
```

### 3.3 教材线（诉求 ① 的官方 PET 口语教材）

PET（B1 Preliminary）口语四部分，每部分做成结构化"场景包"：

| Part | 形式 | 场景包内容 |
|---|---|---|
| Part 1 个人访谈 | 问答 | 常见题库（爱好/学校/家庭）+ B1 目标句型 + 高分表达 |
| Part 2 拍档讨论 | 情境商议 | 情境卡（"去哪儿过生日"）+ 商议句型（suggest/agree/disagree） |
| Part 3 图片描述 | 看图说话 | **图 + 描述脚本骨架**（there is / on the left / probably）+ 参考答案 |
| Part 4 主题延展讨论 | 深入问答 | 话题词表 + 追问链 |

教材接入原则（沿用既有架构）：
- 教材数据放 `frontend/public/data/speak-*.json` + `tools/build_speak_v2.js` 扩展，**加新教材只改数据层**
- 你提供的官方教材 PDF → 我按"新句来源必须核对 PDF 原页"的既有红线整理为场景包（图片转 base64 缩略图或裁剪 png 给 Part 3 用）
- L3 场景层按用户选择的话题注入对应包；`speak_boot` 返回可选话题列表，前端渲染话题选择页

## 4. 缓存策略（诉求 ③，含边界说明）

### 4.1 三级缓存

```
① 服务端缓存（NAS 内存 + SQLite）
   - L2 画像：每天一份，会话间复用
   - L3 场景包：进程内 LRU（教材数据不变）
   - 总结流水线结果：落库，不重复生成

② 百炼上下文缓存（Chat 类接口：总结/画像重建/enrich）
   - L0+L1 固定前缀 → 隐式缓存自动命中（20% 输入价）
   - 显式缓存留给「同一用户 5 分钟内连续重建画像」场景，
     创建 125% / 命中 10%，5 分钟滚动过期；用户规模小，
     预期以隐式缓存为主，不做主动管理

③ Realtime 会话内（无跨会话缓存，靠会话内结构省 token）
   - instructions 在 session.update 一次性下发（L0–L3 合并，约 3.4k tok），
     对话轮次只在会话内累积
   - 跨会话不缓存：Realtime 计费按会话输入输出，重连=新会话，
     前缀缓存对 Realtime 是否生效官方未承诺 → 不作为依赖项
```

### 4.2 Token 预算（单次会话）

| 项 | Token | 说明 |
|---|---|---|
| L0–L1 固定 | ~2k | 含教学法规则 |
| L2 画像 | ~0.6k | 每日一份 |
| L3 场景 | ~0.8k | 单话题 |
| 对话轮次 | 每 10 轮 ~1.5k | 15 分钟会话约 20 轮 |
| 合计 | 会话内 ≤196608 上限的 <1% | 宽裕 |

### 4.3 模型选型优化（2026-11-22 价格核实后修订）

**核心结论：Realtime 用 qwen3.8-omni-flash-realtime，比上一代 qwen3 同级便宜约 75%，且音频 token 换算率更低。**

| 模型 | 音频输入 | 音频输出 | 音频换算 | 30 分钟对话成本 |
|---|---|---|---|---|
| ~~qwen3-omni-flash-realtime~~ | 18.9 元/M tok | 75.1 元/M tok | 输入/输出均 12.5 tok/s | ~1.0 元 |
| **qwen3.8-omni-flash-realtime（选定）** | 6 元/M tok | 12 元/M tok | **输入 7 tok/s、输出 12.5 tok/s** | **~0.15 元** |

qwen3.8 注意两点：① 输出语音时**对应文本也按文本输出计价**（4.5 元/M，量小可忽略）；② 空间音频输入 token ×2（我们不开启）。

| 用途 | 模型 | 单价 | 说明 |
|---|---|---|---|
| 实时对话 | qwen3.8-omni-flash-realtime | 见上 | Function Call / MCP 支持 |
| 会话总结 / 画像重建 / 加词 | qwen3.8-flash | 输入 0.8 元/M、输出 2.7 元/M | 文本，量极小 |
| 跟读发音评分 | 腾讯 SOE 新版 | 后付费 0.005 元/次；资源包 9.9 元/万次（≈0.001 元/次） | ≤20 词计 1 次，跟读句均 ≤20 词 |
| TTS 示范发音 | qwen3-tts-flash | 按字符 | 仅「听发音」按钮，量小 |

### 4.4 每日成本估算（每人每天约 30 分钟口语）

假设：自由对话 25 分钟（流式上传按全 1800s 计，AI 输出语音约 600s）+ 跟读 30 句（SOE 30 次）+ 总结/画像各 1 次。

| 计费项 | 用量 | 单价 | 金额 |
|---|---|---|---|
| Realtime 音频输入 | 1800s × 7 = 12.6k tok | 6 元/M | 0.076 元 |
| Realtime 音频输出 | 600s × 12.5 = 7.5k tok | 12 元/M | 0.090 元 |
| Realtime 文本进出 | 提示词+轮次 ~10k in / ~1.2k out | 1.5 / 4.5 元/M | 0.020 元 |
| SOE 评测 | 30 次 | 资源包 0.001 元/次（后付费 0.15 元） | 0.03~0.15 元 |
| 总结 + 画像 | ~6k in + 0.9k out | 0.8 / 2.7 元/M | ~0.008 元 |
| **合计** | | | **≈ 0.22~0.34 元/人/天** |

**月成本**（30 天）：**约 7~10 元/人/月**；5 个同学 **35~50 元/月**（420~600 元/年）。
即使孩子每天聊满 1 小时，也只翻倍到 ~0.5 元/天/人——成本可控，无烧 Key 风险。
（单价以百炼控制台实价为准；SOE 建议先购 9.9 元调试包再转 15 万次包。）

### 4.5 不用 Realtime 的替代方案对比（2026-11-22 核实，结论：不推荐换）

替代方案是经典流水线：**流式 ASR → 文本 LLM → 流式 TTS**。按 2026-11 百炼实价：

| 组件 | 模型（最新价） | 30 分钟用量 | 金额 |
|---|---|---|---|
| 流式识别 | paraformer-realtime-v2：0.00024 元/秒（≈0.86 元/时）；fun-asr-realtime：0.00033 元/秒 | 1800s | 0.43~0.59 元 |
| 文本对话 | qwen3.8-flash，上下文逐轮累积 ~40k in / 3k out | 20 轮 | ~0.04 元 |
| 流式合成 | qwen3-tts-flash：0.8 元/万字符（按输入字符计） | AI 说 ~600s ≈ 6k~9k 字符 | 0.48~0.72 元 |
| **流水线合计** | | | **≈ 0.95~1.35 元/人/天** |

**比 Realtime（0.22~0.34 元）贵约 4~5 倍**——主要贵在 TTS 按字符计费（AI 说得越多越贵）和 ASR 按秒计费（含静音），而 Realtime 音频输出仅 12 元/M tok。

**效果差异（对口语教学是关键）**：

| 维度 | Realtime 端到端 | ASR+LLM+TTS 流水线 |
|---|---|---|
| 响应延迟 | ~0.5–1s，自然对答 | ASR 端点检测 + LLM + TTS 首包 ≈ **2–3s**，孩子明显觉得"卡" |
| **发音纠错能力** | 模型直接听音频，**能听出孩子发音不准**并纠正 | **致命伤：ASR 会把读错的词自动"纠正"成正确文本**，模型根本不知道孩子读错了——口语教学最核心的能力丢失 |
| 打断/抢话 | 模型原生 VAD，随时打断 | 需自行实现（停 TTS 播放 + 切状态），边界情况多 |
| 语气/情绪/语速理解 | 有（音频直入） | 无（只剩文字） |
| 多组件错误 | 单模型 | 级联：识别错 → 全盘皆错 |
| 文本可控性 | 一般（提示词约束） | **强**（结构化输出、上下文缓存可用、日志全文本） |

**结论**：流水线唯一优势是文本可控+可用 Chat 缓存，但对外语口语陪练而言「听得出孩子发音问题」不可妥协，且成本反而更高 4~5 倍。**维持 Realtime 选型不变**；流水线仅作为 Realtime 服务异常时的降级备份思路记录，不实施。

## 5. 对话中的辅助设计（诉求 ④）：三档脚手架

儿童口语教学的核心原则：**先给时间，再给提示，最后给示范；绝不纠错打断**。

```
检测到困难（模型自主判断：沉默 / 长停顿 / 中文求助 / 明显放弃语气）
  ↓ 第 1 档【等】 英文复述问题 + 简化措辞（recast，等 8 秒）
  ↓ 第 2 档【提示】中文关键词提示："你可以说'周末'，weekend"
  ↓ 第 3 档【示范】简单英文句型 + 中文对照：
        "You can say: I like playing football.
         意思是：我喜欢踢足球。你试试？"
```

**实现机制**（两条腿走路）：

1. **提示词驱动（主）**：L1 教学法层写明三档规则与触发条件，模型自主执行——Realtime 模型对 instructions 遵循度足够好，且零延迟。
2. **Function Call 增强（辅，M2）**：`session.tools` 注册两个客户端工具：
   - `hint(word, cn, sentence)`——模型判定需要时调用，前端在屏幕上同时弹出文字提示卡（语音+文字双通道，对儿童更有效）
   - `praise(score, detail)`——会话中调用 SOE 轻量评测（或直接引用模型自评），屏幕显示星星奖励

**屏幕辅助区**（前端常驻）：
- 实时转写条（当前对话文本，孩子看得到自己说的什么）
- 「怎么说？」按钮——孩子主动求助，前端把当前话题 + 卡点发给 `speak_boot`，由服务端走 chat 接口生成"中文解释 + 简单英文示范句"并以气泡展示（不打断语音流）
- 会话结束报告：本次新学表达 / 纠正点 / 星星数

### 5.5 会后复盘：PET 优化句跟读 + 记忆曲线（2026-11-22 用户新增需求）

**节奏**：单次口语总时长 ~15 分钟 = 实时对话 ≤12 分钟（模型主动收尾）+ **3~5 分钟会后复盘跟读**，趁热打铁。

**流程**（会话结束 → 复盘包 → 跟读评分 → 进记忆曲线 → 后期反复）：

```
会话关闭（前端上报，transcript 已存 speak_log）
  ↓ 服务端取本会话「孩子说的话」，只挑有提升空间的句子（每会话 3~6 句，不凑数）
  ↓ LLM 改写（qwen3.8-flash，~2k tok ≈ 0.002 元）：
      child_said → improved_en（PET B1 标准改写，保留孩子本意）
                 + improved_cn（中文对照）+ focus（语法/词汇/句型哪一类）+ why（一句话中文解释）
  ↓ 生成「复盘包」落库（幂等，按会话 id），前端自动进入复盘跟读页
  ↓ 逐句：看 孩子原话 vs PET 优化句 → 听示范（TTS）→ 跟读 → SOE 评分
  ↓ 评分记账 → 进记忆曲线（SRS），到期反复
```

**记忆曲线规则**（与词汇/阅读错题同语义，红线不改）：
- 句子维度记账：`dims = {focus 项}`（如 `grammar:三单` / `vocab:weekend` / `phrase:would_like`），答对一个维度划掉，全部划掉即毕业
- SOE 分数 ≥85 记「对」（对应维度划掉）；<60 记「错」（该维度重新欠着 + 回 1 天）
- 间隔序列 1/2/4/7/15 天，走完全部维度标全会

**后期反复的三个出口**：
1. **跟读页「口语复盘」队列**：按 due_at 排序，到期的复盘句优先排在教材句库前
2. **下次会话开场热身**：`speak_boot` 把到期复盘句注入 L2，模型先带孩子把这几句重说一遍再进入正题
3. **会话结束报告**：列出「今日待复习句」数量，引导进队列

**数据模型**：新表 `pet_speak_review`（sid=会话:序号、child_said、improved_en、improved_cn、focus、dims、stage/due_at/repeats——SRS 三字段与 Mistake 同构）；合并语义沿用「欠得多」原则。

**验收要点**：复盘句必须是孩子真实说过的话的改写（不臆造没聊过的内容）；改写不超过 B1 水平两句以内长度；孩子原话与优化句并排展示，让孩子看得见"我说的 → 我可以说得更好的"。

## 7. 专业补充建议（你没提但建议纳入）

1. **评分维度对齐 PET 官方**：Part1–4 对应语法词汇/话语管理/发音/互动四个维度，会话报告按这四维给分（1–5 分，剑桥标准），家长看得懂、备考有指向。
2. **话题轮换防厌学**：画像里记录话题履历，模型主动提议"上次聊了宠物，今天试试学校生活？"——复用既有 issues 数据即可。
3. **单会话时长护栏**：儿童注意力 10–15 分钟，会话超 12 分钟模型主动收尾（"今天聊得很棒，明天继续！"），落在 L0 固定层。
4. **隐私与安全**：对话内容只存摘要与 issue 聚合（画像用），**原始音频不落盘**；L0 写明拒绝任何与学习无关的话题引导（儿童安全红线）。
5. **成本可见**：不限会话时长、不设配额（2026-11-22 用户确认）；用量与预估费用按人按天记录，管理员页可见（见 §8）——靠「看得见」而不是「限流」控成本。
6. **与 SOE 打通**：自由对话中模型听出的问题发音（它有 ASR 转写），在会话报告里列出"这几个词发音要练"，一键跳转跟读页对应句——形成「自由对话发现问题 → 跟读精准修」闭环。

## 8. 用量统计（每个用户 + 管理员，只记录不限流）

设计原则（2026-11-22 用户确认）：**对话不限时、不设配额，只做用量与费用记录**；统计粒度到人，管理员看全局。

### 8.1 用量记账表 `pet_usage`

```sql
CREATE TABLE pet_usage (
  user_id    INTEGER NOT NULL,
  day        TEXT NOT NULL,           -- 'YYYY-MM-DD'（按北京时间）
  rt_audio_in_tok   INTEGER DEFAULT 0,   -- Realtime 音频输入 token
  rt_audio_out_tok  INTEGER DEFAULT 0,   -- Realtime 音频输出 token
  rt_text_tok       INTEGER DEFAULT 0,   -- Realtime 文本进出 token
  soe_calls         INTEGER DEFAULT 0,   -- SOE 评测次数
  llm_in_tok        INTEGER DEFAULT 0,   -- 总结/画像/enrich 输入
  llm_out_tok       INTEGER DEFAULT 0,
  est_cost_milli    INTEGER DEFAULT 0,   -- 预估费用（0.001 元为单位，避免浮点）
  PRIMARY KEY (user_id, day)
);
```

### 8.2 记账点（服务端，客户端不可信）

| 计费项 | 记账时机 | 依据 |
|---|---|---|
| Realtime 音频 | 会话关闭时（前端上报会话时长秒数，服务端按 **7 / 12.5 tok/s** 折算并写库） | 官方换算系数；不信任前端 token 数，只信时长 |
| SOE 次数 | `POST /speak/soe_url` 每发一次签名 URL 计 1 次（按 ref_text 词数折算 20 词 1 次） | 服务端天然计数点 |
| LLM token | 总结/画像任务完成后按响应 usage 写库 | API 返回值 |

预估单价（`est_cost_milli` 用）做成**配置**存 `pet_cfg`（key 如 `usage.price_rt_in`），价格变动管理员改配置即可，不用改代码。

### 8.3 统计呈现

- **用户端**：口语首页显示「今日已用」（对话分钟 / 跟读次数）轻量展示，**不置灰按钮、不拦截**
- **管理员页**（/admin 新增「用量」区块）：
  - 当日总览：全站 Realtime token、SOE 次数、预估费用（元，1 位小数）
  - 按用户表格：每人今日/本月 token、次数、预估费用
  - 月度曲线
- 后端 API：`GET /admin/usage?day=`、`GET /admin/usage/summary?month=`

### 8.4 与分期计划的合并

记账归入 **M1（记忆闭环）** 一起做：`speak_sdp` / `soe_url` 本来就要改（注入画像 + 上报后记账），一次改完不返工。M2 时补用户端「今日已用」展示和管理员用量区块的 UI。
