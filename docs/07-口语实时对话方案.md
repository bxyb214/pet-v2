# 07 · 口语实时对话方案

> 目标：把自由对话做成「有教学策略、有记忆、有教材支撑」的 PET 口语陪练。
> 更新：2026-11-23（5+10+15 节奏、161 场景题库、服务端时长）。实现细节见 [dev/speak-15-15](dev/speak-15-15/)。

## 1. 能力与边界

| 已有能力 | 实现 |
|---|---|
| 实时语音对话 | Qwen Realtime WebRTC，浏览器直连；服务端只做 SDP 交换与提示词 |
| 跟读评分 | 腾讯 SOE 新版 + AI 点评双引擎；114 句 / 19 包 |
| 造句 | 11 组 78 句型（`patterns.json`） |
| 场景题库 | 161 个 PET 真题场景（Part 1–4），独立页签 |
| 记忆与复盘 | 每轮回答即时改写为 B1 句；结束页内 5 分钟复盘；SRS 记忆曲线 |
| 练习时长 | 服务端按天累计；跟读/对话按麦克风开口秒数，造句按页面可见时间 |

**边界**：不做听力式答题/判分；口语 Key、对话音频不落盘；不设配额，只记用量。

## 2. 提示词分层（Prefix-Stack）

按变化频率分层，稳定层在前，兼顾教学与缓存命中。

| 层 | 内容 | 规模 / 更新 |
|---|---|---|
| L0 固定 | 角色 Pip、儿童安全红线、输出格式、单会话 12–15 分钟收尾 | ~800 tok，数月一改 |
| L1 教学法 | 三档脚手架、recast 不打断、CEFR B1 目标、PET 四维评分 | ~1200 tok，随教材 |
| L2 画像 | 能力/弱项/今日口语内容/长期记忆摘要 | ~600 tok，每日重建 |
| L3 场景 | 所选场景的话题、目标句型、必备词汇、Part 3 描述脚本 | ~800 tok，按场景注入 |
| L4 会话 | 本次对话轮次与工具调用结果 | 动态 |

L0–L1 全站共享，利于百炼隐式缓存命中；Realtime 在 `session.update` 一次性下发 L0–L3。

## 3. 三条记忆线

### 3.1 当天口语线（强关联）

只注入口语板块自身数据，**不混入词汇/阅读/听力**：

- 今天跟读的包与完成情况；
- 今天练过的场景（Part / 真题编号）；
- 最近 7 天高频错误表达；
- 今日计划任务（1–90 天计划按比例切分）。

### 3.2 长期记忆（压缩，不塞全文）

| 层级 | 存储 | 更新时机 |
|---|---|---|
| 会话摘要 | `speak_logs.summary`（≤150 tok） | 会话结束，文本模型生成 |
| 话题履历 | `speak_profiles.content`（JSON） | 结束累加，防重复话题 |
| 错误档案 | `speak_profiles.content`（issues 聚合 + 频次） | 结束归并 |

画像重建：每天首次会话前，用近 7 天摘要 + 话题 + issues + 当日数据生成，缓存到 `speak_profiles`，跨天失效。

### 3.3 教材 / 场景线

| 部分 | 形式 | 场景包 |
|---|---|---|
| Part 1 | 个人访谈 | 17 分类 / 85 题问答 + B1 目标句 |
| Part 2 | 图片描述 | 89 个真题图场景 + 描述脚本骨架（there is / on the left / probably） |
| Part 3–4 | 讨论与延展 | 55 个真题话题 + 商议/追问链 |

三类合计 161 个场景：17 + 89 + 55。

数据在 `data-src/speak/`，由 `tools/build_speak_v3.js` 生成 `speak.json` v3；加教材只改数据层。

## 4. 15 分钟每日节奏

```text
5 min 跟读   → 10 min 造句 → 15 min 自由对话（10 min 对话 + 5 min 复盘）
```

- 只做计时与提示，不强制中断；三项都完成后当天打勾。
- 计划手动创建：选 1–90 天自动切分；已有计划只显示删除，新建/改长度重置打卡。
- 161 场景是独立题库，每日计划列出当天场景，可从计划或题库进入对话。

### 4.1 对话中的即时优化

```text
孩子说完一轮
  → POST /speak/improve：child_said → improved_en（保留本意）+ improved_cn + focus + dims
  → 气泡下方展示优化句：听示范（TTS）→ 就地跟读（SOE）→ 评分
  → 10 分钟后提示进入复盘（不强制）
```

### 4.2 结束复盘（页内，不设独立页）

```text
session_end（用会话计时计费，用开口秒数计时长）
  → 优化句经 /speak/review/import 落库（按 log + child_said 幂等）
  → 对话页底部展开 5 分钟复盘：逐句重读、评分、进记忆曲线
```

**SRS 规则**（与词汇/阅读错题同语义）：

- 维度 `dims = {grammar:三单, vocab:weekend, phrase:would_like}`；
- SOE ≥85 记为对，划掉对应维度；<60 记为错，该维度重欠并回 1 天；
- 间隔 1/2/4/7/15 天；全部维度划掉即毕业。

**三个复习出口**：到期复盘句、下次会话开场热身（`speak_boot` 注入）、结束报告中的待复习数。

## 5. 缓存与成本

### 5.1 三级缓存

| 层 | 策略 |
|---|---|
| 服务端 | L2 画像每日一份；L3 场景包进程内 LRU；总结落库不重算 |
| 百炼 Chat | L0+L1 固定前缀走隐式缓存（输入价 20%）；显式缓存仅用于 5 分钟内重建画像 |
| Realtime | 无跨会话缓存；instructions 一次下发，轮次只在会话内累积 |

### 5.2 模型与单价（2026-11 核实）

| 用途 | 模型 | 单价 |
|---|---|---|
| 实时对话 | `qwen3.8-omni-flash-realtime` | 音频输入 6 元/M tok、输出 12 元/M tok（输入 7 tok/s、输出 12.5 tok/s） |
| 总结/画像/加词/改写 | `qwen3.8-flash` | 输入 0.8、输出 2.7 元/M tok |
| 跟读评分 | 腾讯 SOE 新版 | 资源包约 0.001 元/次（后付费 0.005） |
| TTS 示范 | `qwen3-tts-flash` | 按字符，仅按钮触发 |

### 5.3 每人每天成本（约 30 分钟口语）

| 项 | 估算 |
|---|---|
| Realtime 音频输入/输出 | 0.076 + 0.090 元 |
| Realtime 文本 | ~0.020 元 |
| SOE 30 次 | 0.03–0.15 元 |
| 总结 + 画像 | ~0.008 元 |
| **合计** | **≈0.22–0.34 元/人/天**（月 7–10 元） |

### 5.4 为什么不换 ASR + LLM + TTS

流水线约 0.95–1.35 元/天（贵 4–5 倍），且 ASR 会把读错的词自动「纠正」成正确文本，**丢掉口语教学最核心的发音纠错**；延迟也从 0.5–1 s 升到 2–3 s。结论：维持 Realtime，流水线仅作故障降级思路。

## 6. 教学脚手架与安全

- 三档策略：**等**（英文复述 + 简化，8 s）→ **提示**（中文关键词）→ **示范**（简单英文 + 中文对照）；绝不纠错打断。
- Function Call：`hint(word, cn, sentence)` 弹提示卡；`praise(score)` 显示奖励。
- 屏幕辅助：实时转写、「怎么说？」气泡（不打断语音）、结束报告（新表达/纠正点/星星）。
- 安全：原始音频不落盘；L0 拒绝与学习无关的话题；单会话 12–15 分钟主动收尾。

## 7. 用量统计（只记录不限流）

- 表 `usages`：按人按天记 `rt_seconds/rt_ai_seconds/token/SOE 次数/LLM token/预估费用`。
- 记账点全在服务端：会话关闭按前端上报时长折算；`/speak/soe_url` 每发一次签 URL 计 1 次；LLM 按响应 usage。
- 单价存 `app_cfg`，改价不改代码。
- 用户首页看「今日已用」；管理员在 `/admin → 用量` 看当日/本月与按人明细。

## 9. 关键约束

- Key 只在服务端（`app_cfg`），SDP 交换才带 Key；前端只拿签名临时地址。
- 复盘句必须是孩子真实说过的改写，不臆造；原话与优化句并排。
- 合并语义、错题 dims 记账是红线，不得擅改（见 [AGENTS.md](../AGENTS.md)）。
