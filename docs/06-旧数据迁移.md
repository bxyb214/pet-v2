# 06 旧数据迁移（ai.wizoom.net MySQL → pet-v2 SQLite）

> 工具：`tools/migrate_legacy.py`（映射纯函数集中在文件头部，`backend/tests/test_migration.py` 全覆盖）

## 运行方式

旧库只在内网（172.16.0.67）可达，本机连不上，所以走「PHP 导出 JSON → 本地迁移」：

```bash
# 1) 在代码服务器上导出（只读，PDO + json_encode）
php /tmp/dump_legacy.php            # → /tmp/legacy_dump.json

# 2) 下载到本机 _backup/，然后本地跑迁移（默认 dry-run）
cd pet-v2/backend
.venv/Scripts/python.exe ../tools/migrate_legacy.py \
    --json ../../_backup/legacy_dump_YYYY-MM-DD.json \
    --sqlite ../_work/petmig/pet.db --execute
```

也支持直连（能连旧库的机器上）：
`--mysql "mysql+pymysql://<user>:<pass>@<host>:3306/ai-wizoom?charset=utf8mb4"`

- **默认 dry-run**：只打印映射统计，不写库；确认数字后加 `--execute`。
- 新库表不存在时自动建表；已存在的用户按用户名匹配跳过（不覆盖），学习数据按 user_id 幂等 merge。
- `--plan-days`（默认 30）：旧站计划天数是 `js/app.js` 里写死的 `PLAN_DAYS = 30`，库里只存做过的那几天。
  不按 30 兜底的话，「做了 23 天」会被误判成「23 天计划已全部完成」。

### 改线上库的正确姿势

SQLite 单文件，改之前一定先停 API 再动手，否则 WAL 会分叉：

```bash
docker compose stop api
cp data/pet.db* /tmp/petmig/            # db + -wal + -shm 三个都要（WAL 里有未合并的写入）
# 本地迁移、校验、PRAGMA wal_checkpoint(TRUNCATE) 合并成单文件后传回
docker compose start api
```

## 映射规则

| 旧表 | 新表 | 规则 |
|---|---|---|
| pet_users | users | 只迁 status=active；bcrypt（$2y$）哈希原样迁移，**登录成功自动升级 argon2**；role=admin → is_admin |
| pet_codes | invite_codes | 只迁 active=1 且未用完的码 |
| pet_mastery（一行一维度） | mastery | 按 word_id 合并维度逗号串 |
| pet_mistakes | mistakes | dims_json 数组 → dims 逗号串；stage=0 / due_at=last_at 日期（旧欠账全部视为到期）/ repeats=0；空维度（已毕业）跳过 |
| pet_progress | progress | 只迁阅读：`reading::t{N}p{K}` → `read:t2:{N}:{K}`（N≤6）/ `read:t1:{N}:{K}`（N≥101）；idx>0 另记 `rstudy:{book}:{N}:{K}` 续学位置；plan/browse 来源跳过 |
| pet_plan（exam=pet） | plans | length=最大天；days_done=state='done' 的天；exam=ket 跳过并报告 |
| pet_speak | speak_logs | scene→ref；issues_json 里对象归一为字符串 |
| pet_speak_day | speak_days | 直迁 |
| pet_session / pet_tokens / pet_ai_usage | — | 跳过（v2 无对应 / 重新登录 / 用量未迁） |

## 密码兼容（security.py）

- `verify_password` 先识别 bcrypt 前缀（$2y$/$2a$/$2b$）走 bcrypt 校验，否则走 argon2。
- 登录成功且为旧哈希 → 立即重哈希为 argon2 并落库（无感升级）。

## 注意

1. **先停旧站写入**再迁移（或迁移后旧站只读），否则两边数据会分叉。
2. 迁移后让同学登录旧密码验证；密码只在他们各自下次登录时升级。
3. KET 计划、旧 quiz session、AI 用量统计本次不迁；如需要再单独补。
4. 真实执行前先 dry-run 抄一遍统计数字存档，写入后再核对一遍。

- 阅读计划（`reading_length`）旧站没有，保持 0，由用户在新站自行创建。

### 踩过的坑

1. `created_at` 从 JSON 来是字符串，SQLAlchemy 的 SQLite DateTime 只收 datetime → 统一 `_dt()` 解析。
2. 迁移前必须连 `-wal` 一起拷，否则丢最后一次写入；合并后 `PRAGMA journal_mode=DELETE` 再传回，更干净。
3. `pet_app` 账号只授权给 `127.0.0.1`，`mysql -upet_app` 走 socket（localhost）会 Access denied，要加 `-h127.0.0.1`。
