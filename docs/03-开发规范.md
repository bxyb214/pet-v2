# 03 · 开发规范

> 适用于本仓库的所有改动。目标是让代码可维护、协作可预期，同时不再为每个小功能维护过程文档。
> 需求基线见 [01](01-需求清单.md)，架构见 [02](02-技术架构.md)，功能编号见 [04](04-功能清单.md)。

## 1. 改动流程

| 改动规模 | 做法 |
|---|---|
| 文案、样式、单页小修 | 直接改 + 跑相关测试/构建 |
| 跨模块、接口、数据结构、依赖 | 先用几段话说明方案与影响面，再动手 |
| 触碰红线（§5） | 必须说明并获用户确认 |

- 不再新建 `docs/dev/`：功能的「当时为什么这样做」由 git 提交记录承载。
- 稳定的设计结论写进 `docs/02`、`05`、`07`、`08`；能力变化同步到 `docs/04`。
- 完成前自检：相关测试、`npm run build`（前端改动）、页面/接口实测，缺一不得宣称完成。

## 2. 代码分层

### 后端（`backend/`，Python 3.12）

- `api/v1/` 路由薄：参数校验 + 调 service；业务在 `services/`；模型在 `models/`。
- schema 只由 Alembic 管理，禁用 `create_all`；迁移必须可回滚。
- 全量类型注解；Pydantic v2 请求/响应；模块 snake_case、类 PascalCase、常量 UPPER。
- 错误统一 `{"code": "...", "message": "..."}`；业务错误码集中定义。
- 配置用 pydantic-settings；**密钥只从环境变量或管理页（`app_cfg`）读取**。
- 单文件 ≤ 400 行。

### 前端（`frontend/`，Vue 3）

- `<script setup lang="ts">`，Props/Emits 显式类型。
- HTTP 全部经 `src/core/api.ts`，组件内禁止裸 `fetch`。
- 同步/合并、计划、测验、SOE 等纯逻辑放 `src/core/`，不写进组件；核心逻辑须有 vitest。
- 路由 `meta`（subject/module/crumbs/tabs/width）驱动布局，新增页面必须补。
- 样式只引用 `tokens.css` / Naive UI 主题，不自创颜色与字号。
- 交互约定：拼写、看义选词、阅读答题前不朗读；仅「看词选义」答题前发音。
- 音频路径用 ASCII slug；单文件 ≤ 400 行。

## 3. 测试与构建

```bash
cd frontend && npm test
cd frontend && npx vitest run src/core/merge.test.ts   # 单文件
cd frontend && npm run build                           # vue-tsc + vite build
cd backend  && .venv/bin/python -m pytest tests/ -q
cd backend  && .venv/bin/python -m pytest tests/test_merge.py -q
```

- 后端必须覆盖：合并算法、错题 dims 记账、计划切库、付费闸门。
- 前端必须覆盖 `src/core/` 的合并、计划、测验、SOE、句库等纯逻辑。
- 必须保持的不变量：① dims 空 → 移出错题本；② 409 → 合并重试成功；
  ③ 四库全测完才打勾；④ 计划模式强制全维度。
- 前端测试与构建用 Node 22；Node 26 的实验性 `localStorage` 会破坏 vitest/jsdom。

## 4. 依赖

- 后端 `pyproject.toml` + venv/pip；前端 `package.json` + npm，提交 lock。
- 新依赖须先说明：用途、为何不用现有依赖、维护活跃度。
- 基线：fastapi、uvicorn、sqlalchemy、alembic、pydantic(+settings)、argon2-cffi、bcrypt、pyjwt、httpx、pytest 系；
  vue、vue-router、pinia、naive-ui、@vicons/ionicons5、vite、typescript、vitest、@vue/test-utils。
- 开发/运维专用（不进生产镜像）：paramiko（`deploy_nas.py` / `sync_assets.py` 的 SSH/SFTP），放在 `[dev]` extra。
- `deploy/tts/` 是独立 sidecar（Piper + onnxruntime），依赖写在 `deploy/tts/requirements.txt`，
  **不加入** api 的 `pyproject.toml`；api 只通过 HTTP 调 `tts:8100`，缺少 sidecar 时本地 TTS 关闭并回退浏览器朗读。

## 5. 红线（违反即不得交付）

- 同步合并语义不得擅改：mastery/mistakes 并集、progress seen 并集 + idx 取大、plan 并集、409 冲突合并重试。
- 错题本维度记账不得擅改：答错全维度重欠、答对划单维、dims 空自动移出、不可手动删除。
- 密钥只从环境变量或管理页读取，禁止入库、入 git、入文档。
- 不提交 `frontend/dist/`、`data/`、`*.db`、`.env`、音频/媒体文件。

## 6. Git 与部署

- 分支：`main`（可部署）+ `feat/xxx`、`fix/xxx`。
- Commit：`type(scope): summary`，type ∈ feat/fix/docs/test/refactor/chore。
- 部署与回滚见 [06](06-部署与运维.md)；生产发布优先用 `tools/deploy_nas.py`。
