# PET 备考网站 v2 — 需求清单（v1.0，已确认冻结）

> 状态：**已确认（2026-11-22），冻结为开发基线**。后续变更走变更记录。
> 目标环境：飞牛 NAS（fnOS），Intel N150 / 8GB 内存 / NVMe PCIe 3.0 512GB。已有端口映射 + HTTPS。

---

## 1. 项目背景与目标

现有 PET 站点（`PET/` 纯前端 + `/ai/api/index.php` PHP 后端 + MySQL）功能已成型但架构会越来越难维护：
前端是大量原生 JS 手工拼装，后端单入口 PHP，数据同步靠 localStorage + 乐观锁，扩展成本高。

v2 目标：
1. **前后端分离重构**：FastAPI 后端 + 现代前端框架，代码可测、可扩展。
2. **迁移到飞牛 NAS 自托管**：脱离现有跳板机链路，Docker 化部署。
3. **功能等价迁移**：现有四个学习板块 + 用户/同步体系全部保留，数据可迁移。

## 2. 迁移范围（现状功能盘点，v2 必须覆盖）

### 2.1 词汇板块
- 四个词库：必默 / 高频 / 固搭 / 同义（数据源 `js/data.js`，含音频）。
- 练习题型：拼写、看词选义、看义选词；答题前/后朗读规则沿用现有约定。
- 掌握度记录（mastery）、错题本。
- **错题本规则（保留，不改语义）**：不可手动删除；按维度记账 `dims={w2m,m2w,spell}`；答错→全维度重新欠；答对单维度→划掉该维度；dims 空→自动移出。

### 2.2 阅读板块
- 多教材分组（Trainer 1 从 test 101 起编号），按教材折叠展示。
- 句子级数据：`en/cn/key/quiz` + `tense/parse/gram/refs/gq`（10 天 / 42 考点语法体系）。
- 数据仍由构建脚本（现 `tools/build_reading.js`）从 `_work/gen/testN.json` 生成，v2 保留"源 JSON → 构建产物"链路。

### 2.3 听力板块
- Trainer 1 六套题：Part1 图选 / Part2 三选一 / Part3 笔记填空 / Part4 采访三选一。
- 音频按 Part 切片（`tN-pK.mp3`），选项配图仅保留在数据中。
- 字幕时间轴对齐（原文随进度高亮、自动滚动，可隐藏）。
- Part 页为纯播放器：0.8 / 0.9 / 1.0 / 1.1 / 1.2 五档倍速；题目与作答在纸质卷完成，页面不判分、不记错题。

### 2.4 口语板块
- 五个标签：计划、跟读、造句、对话、题库；复盘并入自由对话，不再单独设页。
- 计划像词汇计划一样手动创建：选 1–90 天，自动切分内容。**已有计划只显示删除，没有计划才显示创建**；删除后打卡记录保留，可重新创建。
- 每日节奏：**5 分钟跟读 + 10 分钟造句 + 15 分钟自由对话（10 分钟对话 + 5 分钟复盘）**，只提示不强制。
- 新建/修改计划会重置打卡进度；一天完成 = 跟读 + 造句 + 对话三项都做。
- 练习时长按「真正开口」的秒数在服务端按天累计（造句按页面练习时间），刷新不丢。
- 对话中每轮回答由 AI 即时改写成 PET B1 句并可就地跟读；结束后的 5 分钟集中复盘本次优化句。
- 161 个 PET 真题场景作为独立题库（二级页签），每日计划列出当天场景；首页只保留跟读/造句/对话三个每日入口。
- Qwen Realtime WebRTC 浏览器直连；后端职责：拼提示词 + SDP 交换（带 Key）+ 记录存储。Key 只存服务端，接口只回尾号。
- 用户权限位：`speak`（默认关，admin 开/关，管理员自己也可关）、`listen`（默认开，可关）。

### 2.5 计划板块
- 30 天计划：按比例切四库、当天四库全测完才打勾、计划模式强制重考全部维度。
- 完成状态云同步。

### 2.6 用户与数据同步
- 账号密码（密码哈希）、长期 token、首次初始化 claim。
- 多端同步：本地缓存 + 服务端，字段级合并（mastery/mistakes 并集、progress 并集+取大、plan 并集）。
- admin 用户管理（开权限、看进度）。

## 3. 新增需求（v2 重构点）

| # | 需求 | 说明 |
|---|------|------|
| N1 | NAS 部署 | Docker Compose 一键起：nginx + FastAPI(+uvicorn) + 数据库；资源占用控制在 1GB 内存以内 |
| N2 | 前后端分离 | 前端构建为静态产物由 nginx 托管；后端纯 REST API |
| N3 | 数据迁移 | 一次性迁移脚本：MySQL `pet_*` 8 张表 → v2 数据库；音频/图片文件搬迁 |
| N4 | 认证升级 | 长期 token 换成 JWT（access + refresh），密码哈希 bcrypt/argon2 |
| N5 | 备份 | 数据库定时备份（NAS 上 cron/计划任务），保留 N 份 |
| N6 | 管理后台 | admin 页面：用户管理、权限、口语 Key 配置（替代 `pet_cfg` 直改库） |
| N7 | 结构化构建 | 词汇/阅读/听力/口语源数据统一进 `data-src/`，一个构建命令产出前端静态数据 |
| N8 | 邀请码注册 | 注册需邀请码（`invite_codes` 表，沿用旧 `pet_codes`），邀请码面向几个同学开放 |

## 4. 非功能需求

- **性能**：家庭 2–5 用户并发，API P95 < 200ms；静态资源走 nginx 缓存头。
- **资源**：全部容器常驻内存 ≤ 1GB（N150 / 8GB 环境富余）。
- **安全**：仅内网/自用域名访问；HTTPS 由 NAS 层或 nginx 终结；口语 Key 不出服务端。
- **可维护**：API 版本化（`/api/v1`）、数据库迁移工具管理 schema、代码 lint+测试齐备。

## 5. 决议记录（2026-11-22 确认）

| # | 问题 | 决议 |
|---|------|------|
| 1 | 前端框架 | **Vue 3**（+ Vite + TypeScript）✔ |

| 3 | 访问方式 | 已有**端口映射 + HTTPS**，后端容器内部走 HTTP，TLS 在前置层终结 |
| 4 | 旧数据迁移 | **需要迁移**（MySQL `pet_*` 8 张表 + 音频/图片文件 → v2） |
| 5 | 旧站去向 | **先不下线**，`ai.wizoom.net/PET/` 保持可用至 v2 稳定 |
| 6 | Qwen Key | 迁到 **NAS 环境变量**注入 api 容器 |
| 7 | 用户范围 | **邀请码注册**，只对几个同学开放（→ N8） |
