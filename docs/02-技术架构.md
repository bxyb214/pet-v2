# PET v2 — 技术架构（v0.1 草案）

> 目标硬件：飞牛 NAS（fnOS），N150 / 8GB / NVMe 512GB。Docker 化部署，nginx 对外。

## 1. 总体架构

```
浏览器 (孩子/家长设备)
   │  HTTP(S)
   ▼
┌─────────────────── fnOS NAS (Docker) ───────────────────┐
│                                                          │
│  nginx 容器                                              │
│   ├─ /            → 前端静态产物 (Vue3 build dist)        │
│   ├─ /audio /img  → 静态媒体文件 (volume 挂载)            │
│   └─ /api/*       → 反代 uvicorn:8000                    │
│                                                          │
│  api 容器 (FastAPI + uvicorn)                            │
│   ├─ REST /api/v1  (auth, words, reading, listening,     │
│   │                speaking, plan, sync, admin)          │
│   └─ WebRTC SDP 中转 (Qwen Realtime，仅信令)              │
│                                                          │
│  SQLite (volume)  ← 数据库单文件，备份=拷文件             │
│  /data volume     ← config、音频、图片、备份              │
└──────────────────────────────────────────────────────────┘
```

资源预算：nginx ~20MB，uvicorn(2 worker) ~150MB，SQLite 进程内，合计 < 300MB，8GB 富余。

## 2. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | **Vue 3 + Vite + TypeScript** | 中文生态好、单文件组件贴近现有页面结构、构建快、产物小 |
| UI | 轻量自绘组件 + 少量 headless（沿用现站视觉） | 现站已有成熟交互风格，不引入重型 UI 库 |
| 状态 | Pinia + 本地持久化插件 | 离线可玩，联网后与服务器合并同步（沿用现有合并语义） |
| 后端 | **Python 3.12 + FastAPI + uvicorn** | 用户指定；类型化、自动 OpenAPI 文档 |
| ORM | SQLAlchemy 2.x + Alembic | schema 迁移可控 |
| DB | **SQLite（WAL 模式）**（已确认，2026-11-22） | 单文件零运维，家庭并发毫无压力 |
| 认证 | JWT access(2h) + refresh(60d)，argon2 密码哈希 | 替换现有自研 token 表 |
| 部署 | Docker Compose（nginx + api 两容器） | fnOS 原生支持，一键起停 |
| CI | GitHub Actions / 本地脚本 → 构建产物 + 镜像 → 推送 NAS → compose up | 见 03 规范「自动化部署」 |

## 4. API 设计（REST /api/v1）

| 组 | 端点（示例） | 对应旧能力 |
|----|-------------|-----------|
| auth | `POST /auth/login` `POST /auth/refresh` `POST /auth/claim` | pet_users / pet_tokens |
| sync | `GET /sync/pull?since=` `POST /sync/push`（带 rev 乐观锁，冲突 409+最新） | pet_mastery/mistakes/progress/plan 同步 |
| plan | `GET/PUT /plan/day/{n}` | pet_plan + done_flags |
| speak | `POST /speak/boot` `POST /speak/sdp` `POST /speak/log` | speak_boot/speak_sdp/speak_log |
| admin | `GET/PUT /admin/users` `PUT /admin/perms` `GET /admin/cfg` | 用户管理、perms、pet_cfg |
| media | 不走 API；nginx 直接服务 `/audio/` `/img/` | 静态音频/图 |

**合并语义保持不变**（这是现有同步的精髓，重构不许改）：
- mastery / mistakes：字段并集
- progress：seen 并集、idx 取大
- plan：完成状态并集
- 冲突：返回 409 + 服务端最新数据，前端合并后重试

## 5. 数据模型（旧 → 新映射）

| 旧表 (MySQL pet_*) | 新模型 | 备注 |
|---|---|---|
| pet_users | users | +argon2 哈希、perms 保留位标记、data_rev 乐观锁、current_course（多课程：KET/PET/FCE/初中英语，同时只学一门） |
| pet_tokens | 废弃 | JWT 无状态化 |
| pet_mastery | mastery（user_id, word_id, mastered_dims） | 合并=并集 |
| pet_mistakes | mistakes（+ SRS 字段：stage/due_at/repeats） | 记忆曲线间隔 1/2/4/7/15 天，走完标「全会」；合并=取「欠得多」的状态 |
| pet_progress | progress（user_id, key, seen, idx） | 合并=seen 并集+idx 取大 |
| pet_plan | plans（+length 30/40 可选） | 合并=完成并集 |
| pet_session | sessions | 学习记录 |
| pet_speak / pet_speak_day | speak_logs / speak_days | 平移 |
| pet_cfg | app_cfg（Key 类配置存库，管理页编辑；env 只留 JWT secret 等基础设施） | |
| pet_codes | invite_codes | 邀请码注册 |
| （新增） | usage_logs（user_id, kind=tts/qwen, ts, tokens） | M4 用量统计，日/周/月/年聚合 |
| （新增） | user_materials | H3 个人中心「学习材料」开关 |
| （新增） | custom_words（user_id, word, pos, definition, example_en, example_cn, source） | V11 手动添加单词：AI 自动配例句/词性/释义，可人工修正；纳入测验与错题本 |
| （改动） | plans | 不预初始化：用户任意自选天数后生成（不限于 30/40）；支持删除后重新生成（days_done 清空） |

v2 架构预留**多学科**扩展（数学/语文/英语 → 课程 KET/PET/FCE/初中英语 → 教材），首版只实现英语。

迁移脚本 `scripts/migrate_old_data.py`：连旧 MySQL → 读全表 → 写入新 SQLite → 校验行数与抽查。

## 6. 部署（fnOS）

1. fnOS 的 Docker 套件中导入 `deploy/docker-compose.yml`（两服务：`nginx`、`api`；volume：`./data`、`./media`）。
2. 媒体文件（audio/img 约数百 MB）放 NAS 共享目录，volume 挂进 nginx。
3. HTTPS：**已有端口映射 + HTTPS**（用户侧已就绪）。容器内 nginx/api 走 HTTP，TLS 由前置层（路由器/NAS 反代/证书服务）终结；如后续改由 nginx 容器直接挂证书，仅需加 volume + server 块调整。
4. 注册策略：邀请码制（`invite_codes` 表，沿用旧 `pet_codes` 数据）。
5. 备份：NAS 计划任务每日 `sqlite3 data.db ".backup backup/xxx.db"` + 媒体目录快照，保留 14 份。
6. 回滚：镜像带版本 tag，compose 切回旧 tag 即可；数据库变更靠 Alembic downgrade。
7. 旧站 `ai.wizoom.net/PET/` **不下线**，v2 稳定后再议。

## 7. 前端同步引擎（沿用语义、重写实现）

- 数据层 Pinia store + IndexedDB/localStorage 持久化。
- 本地修改 → dirty 标记 → 防抖 1.2s push；登录/每 45s 静默 pull。
- push 带 `rev`，409 时合并服务端数据重试（合并规则见 §4）。
- 保留 `__PET_LOCAL_ONLY` 式的强制本地开关（测试用）。
