# 06 · 部署与运维

> 部署、备份、回滚、旧数据迁移的**唯一入口**。本地 macOS 与飞牛 NAS 共用 `deploy/docker-compose.yml`。
> AI Key 不走环境变量：部署后在 `/admin` 填写，存 `app_cfg` 表，接口只回尾 4 位。

## 1. 部署形态

`deploy/docker-compose.yml` 起两个容器：

| 服务 | 镜像 | 端口 | 职责 |
|---|---|---|---|
| `nginx` | `nginx:1.27-alpine` | 宿主 `8088` → 容器 `80` | 静态站 + `/api/` 反代 |
| `api` | `pet-api:latest`（`backend/Dockerfile`） | 内部 `8000` | FastAPI + Alembic 迁移 |

```text
浏览器 ──HTTP(S)──▶ 前置 TLS（路由器 / NAS 反代）──▶ nginx:8088
                                                     ├─ /       → ../frontend/dist
                                                     └─ /api/*  → api:8000
api 挂载 ../data → /app/data   （pet.db、TTS 缓存，必须持久化）
```

- `api` 启动命令：`alembic upgrade head && uvicorn ... --workers 2`。
- nginx 直接挂载 `../frontend/dist`，**compose 不构建前端**，必须先 `npm run build`。
- 首次启动自动建表；健康检查每 30 秒探测 `/api/v1/healthz`。

## 2. 本地 macOS

### 2.1 前置

- Docker Desktop 已安装并启动。
- Node 18+（建议 20+）、Python 3.12（只跑后端单测时需要）。

Docker Desktop 未把 CLI 加进 PATH 时：

```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
export DOCKER_CLI_PLUGIN_EXTRA_DIRS="/Applications/Docker.app/Contents/Resources/cli-plugins"
docker version && docker compose version
```

### 2.2 一次性准备

```bash
# 1) 环境变量（deploy/.env 已 gitignore）
cd deploy
cp .env.example .env
openssl rand -hex 32          # 把输出填进 PET_JWT_SECRET

# 2) 构建前端（产物进 frontend/dist，nginx 直接读取）
cd ../frontend
npm install
npm run build

# 3) 运行期数据（不在 git 里）：从 NAS 同步
#    frontend/dist/data/*.json → frontend/public/data/ 与 frontend/dist/data/
#    frontend/dist/audio/      → frontend/public/audio/ 与 frontend/dist/audio/

# 4) 数据库（可选）
mkdir -p ../data              # 放 data/pet.db；空库也能启动
```

- `frontend/public/` 是源目录，重新 build 会带进 `dist/`；`dist/` 是 nginx 实际读取处，改完立即生效。
- `vite.config.ts` 设了 `emptyOutDir: false`，**不要手动清空 `dist/`**（里面含 85 MB 音频）。
- 拷库前先停 NAS 上的 api，或用 SQLite `.backup` 生成一致快照；不要单独拷 `-wal` / `-shm`。

### 2.3 启动与验证

```bash
cd deploy
docker compose up -d --build

curl -s http://localhost:8088/api/v1/healthz   # {"status":"ok",...}
curl -I http://localhost:8088/                  # 200
curl -I http://localhost:8088/data/banks.json
curl -I http://localhost:8088/audio/listen/t1-p1.mp3
```

浏览器打开 <http://localhost:8088>。空库首次用邀请码 `claim` 注册，第一个账号自动成为管理员。

### 2.4 本地常用命令与排障

```bash
cd deploy
docker compose logs -f api        # 后端日志
docker compose logs -f nginx      # nginx 日志
docker compose restart            # 重启
docker compose stop / start       # 停止 / 再启动（保留容器与数据）
docker compose down               # 删容器和网络；data/、dist/ 是 bind mount，不受影响
```

| 现象 | 处理 |
|---|---|
| `docker: command not found` / `compose: unknown command` | 执行 §2.1 的两个 `export` |
| `8088` 被占用 | `lsof -nP -iTCP:8088 -sTCP:LISTEN`；改 compose 的 `8088:80` |
| 页面能开但板块为空 | 检查 `frontend/dist/data/` 是否有 4 个 JSON |
| 听力无声 | 检查 `frontend/dist/audio/listen/*.mp3` |
| 首次构建慢 | 在 `deploy/.env` 覆盖 `PIP_INDEX_URL` 换源 |

## 3. 飞牛 NAS（fnOS）

### 3.1 准备

1. 应用中心安装 **Docker**（自带 `docker compose`）。
2. 系统设置开启 **SSH**。
3. 在 NVMe 存储建目录，例如 `/vol1/1000/docker/pet-v2/`，项目与 `data/` 都放这里。
4. HTTPS：确认路由器/NAS 反代把外部 HTTPS 转到 `NAS内网IP:8088`；容器内只走 HTTP。
5. 国内拉镜像慢时，在 Docker 设置里配置镜像加速。
6. 磁盘预留 ≥2 GB（镜像 + dist 85 MB 音频 + 数据库/TTS 缓存）；时区已固定 `Asia/Shanghai`。

### 3.2 首次部署

```bash
# 代码与 frontend/dist 一并上传到 /vol1/1000/docker/pet-v2/
cd /vol1/1000/docker/pet-v2/deploy
cp .env.example .env && nano .env      # PET_JWT_SECRET
docker compose up -d --build
curl http://127.0.0.1:8088/api/v1/healthz
```

首次初始化：打开 `/register`，用预置的未使用邀请码创建管理员，随后在 `/admin` 填写 Qwen、业务空间 ID、腾讯 SOE 配置。

上线首测清单：

1. 手机/平板登录，能打开单词/阅读/听力（首次会弹麦克风权限）。
2. 口语·跟读：AI 点评 + 腾讯 SOE 都有分数。
3. 口语·对话：10 分钟提示 → 结束复盘 → 优化句可评分。
4. 造句页：AI 能判定；`/admin → 用量` 有数字。

### 3.3 NAS 特性与坑

- **docker 需要 sudo**：`admin` 不在 docker 组时，`docker info` 报
  `permission denied ... docker.sock`。`tools/deploy_nas.py` 会自动切 `sudo -S`；
  手写命令时注意 `sudo cmd1 && cmd2` 只提权 `cmd1`，要写成 `sudo sh -c "cmd1 && cmd2"`。
- **镜像加速可能 401**：`docker.fnnas.com` 对 `python:3.12-slim` 返回 401 时，先从可达源拉取再打官方标签：

  ```bash
  sudo docker pull docker.m.daocloud.io/library/python:3.12-slim
  sudo docker tag  docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim
  ```

- `backend/Dockerfile` 默认走清华 PyPI；`deploy/.env` 的 `PIP_INDEX_URL` 可覆盖。
- WebRTC / SOE 是浏览器直连第三方，**不经过 NAS**；外网必须 HTTPS（或 localhost），否则麦克风不可用。
- **Windows 打包后静态资源 403**：隔着 Windows 打的 tar，文件 mode 常为 `000`，nginx worker 无读权限。
  `tools/deploy_nas.py` 解包后自动 `chmod -R a+rX frontend/dist`；手工上传 `dist/` 时需自己补这一步。
- 2026-11-22 实测基线：fnOS / Debian 12，Docker 28.5.2，api ≈90 MB、nginx ≈5 MB，`/vol1/1000` 390 GB 可用。

### 3.4 开发/预发布环境（8089，与生产并行）

同一台 NAS 上再起一套独立容器，用来先验证待发布版本，生产 8088 不受影响。

| 项 | 生产 `prod` | 开发 `dev` |
|---|---|---|
| 项目目录 | `/vol1/1000/docker/pet-v2` | `/vol1/1000/docker/pet-v2-dev` |
| Compose | `deploy/docker-compose.yml` | `deploy/docker-compose.dev.yml` |
| 端口 | `8088` | `8089` |
| 镜像 tag | `pet-api:latest` | `pet-api:dev`（避免覆盖生产镜像） |
| 数据库 | `<目录>/data/pet.db` | `<目录>/data/pet.db`（独立） |
| AI 行为 | 管理页配置，真实调用 | `PET_DEV_MODE=1`，模拟返回 |

```bash
# 一键部署 / 查看状态（首次会生成 dev 专属 deploy/.env）
NAS_PASS='<密码>' python tools/deploy_nas.py deploy --host 192.168.1.10 --profile dev
NAS_PASS='<密码>' python tools/deploy_nas.py ps     --host 192.168.1.10 --profile dev

# 用生产库一致快照重置开发库（只对 dev 生效，会停/启 dev api）
NAS_PASS='<密码>' python tools/deploy_nas.py seed-db --host 192.168.1.10 --profile dev
```

- dev 的 `.env` 独立生成：独立 `PET_JWT_SECRET`、`PET_DEV_MODE=1`、`PET_DEV_PORT=8089`，与生产 token 互不相通。
- 开发库默认由生产库一致快照复制（`seed-db`）：账号、密码哈希、学习数据与生产相同；
  JWT secret 不同，切到 8089 后需重新登录。两套 `data/` 目录完全隔离，dev 写入不影响生产。
- `seed-db` 流程：生产容器内 `sqlite.backup` 快照 → 停 dev api → 覆盖 dev `pet.db`（清 WAL/SHM）→ 启动；
  快照保留在 `pet-v2/data/backup/pet-seed-<时间戳>.db` 便于回溯。
- 要验证真实 AI：把 dev 的 `deploy/.env` 改成 `PET_DEV_MODE=0` 后
  `docker compose -f docker-compose.dev.yml up -d api`。注意复制生产库会把 `app_cfg` 里的 AI Key 一并带来，
  建议先到 dev 的 `/admin` 换成独立 Key，避免与生产共用额度。
- 标准发布顺序：`--profile dev` 部署并验证 → 提交代码 → `--profile prod` 更新生产。
- 两套环境共用镜像层缓存，dev 首次构建后，后续发布通常 1 分钟内完成。

## 4. 日常运维

### 4.1 更新

| 改动 | 操作 |
|---|---|
| 前端 | 本地 `npm run build` → 上传新 `dist/` → `docker compose restart nginx` |
| 后端 | 上传新 `backend/` → `docker compose up -d --build api`（启动时自动迁移） |
| 整站 | 推荐 `python tools/deploy_nas.py deploy --host <IP> --profile dev\|prod`（打包、上传、chmod、构建、健康检查一条龙） |
| 配置 | 在 `/admin` 修改 AI Key / 模型 / 单价，无需重启 |

`tools/deploy_nas.py` 封装了打包、上传、sudo 探测与 compose 更新，NAS 日常发布优先用它。

### 4.2 备份与恢复

```bash
# 停写后做一致快照（WAL 模式）
docker compose stop api
sqlite3 data/pet.db ".backup 'backup/pet-$(date +%F).db'"
docker compose start api

# 恢复：停 api → 用备份替换 data/pet.db → 启 api
```

- 建议 fnOS 计划任务每日备份，保留 14 份；媒体目录可单独快照。
- 只迁库时不要只拷 `pet.db`：WAL 未合并会丢最后一次写入；用 `.backup` 或 `wal_checkpoint(TRUNCATE)`。
- **不要在容器运行时用宿主机 `sqlite3` 改库**，容易触发 `disk I/O error`；用 `docker compose exec api python ...` 或停 api 后操作。

### 4.3 回滚

镜像带版本 tag 时，compose 切回上一 tag 并 `up -d`；数据库用 `alembic downgrade -1` 回退，迁移必须可逆，不可逆迁移需在设计文档声明。

### 4.4 开发/测试模式

测试环境没有 AI Key 时，在 `deploy/.env` 设置：

```bash
PET_DEV_MODE=1
docker compose up -d --build api
```

- 顶栏用户名位置显示 **DEV**，用户名与头像隐藏。
- Realtime 对话 / SOE 跟读走前端模拟；`improve`、`check`、`help`、`review`、`enrich` 返回确定性结果；
  `tts` 返回提示音；`sdp` / `soe_url` 直接 503，**不发起任何外部调用**。
- 正式部署保持 `PET_DEV_MODE=0`（`.env.example` 默认值），行为与原来一致。
- 设计说明见 [docs/dev/dev-mode](dev/dev-mode/02-design.md)。

## 5. 旧数据迁移

> 一次性操作，已于 2026-11-22 执行。工具：`tools/migrate_legacy.py`，映射纯函数由 `backend/tests/test_migration.py` 覆盖。

旧 MySQL 仅内网可达，走「PHP 导出 JSON → 本地迁移」：

```bash
# 1) 代码服务器导出（只读）
php /tmp/dump_legacy.php                       # → /tmp/legacy_dump.json

# 2) 本地迁移（默认 dry-run，确认统计后加 --execute）
cd backend
.venv/bin/python ../tools/migrate_legacy.py \
    --json ../../_backup/legacy_dump_YYYY-MM-DD.json \
    --sqlite ../data/pet.db --execute
```

也可在能连旧库的机器直连：`--mysql "mysql+pymysql://<user>:<pass>@<host>:3306/ai-wizoom?charset=utf8mb4"`。

| 旧表 | 新表 | 规则 |
|---|---|---|
| `pet_users` | `users` | 只迁 active；bcrypt `$2y$` 原样保留，登录成功后自动升级 argon2；`role=admin` → `is_admin` |
| `pet_codes` | `invite_codes` | 只迁 active 且未用完的码 |
| `pet_mastery` | `mastery` | 按 `word_id` 合并维度 |
| `pet_mistakes` | `mistakes` | dims 数组 → 逗号串；旧欠账视为到期；空维度跳过 |
| `pet_progress` | `progress` | 阅读：`reading::tN pK` → `read:t{book}:{N}:{K}`；另记 `rstudy:` 续学位置 |
| `pet_plan` | `plans` | `length` = 最大天；`days_done` = state='done'；KET 跳过并报告 |
| `pet_speak` / `pet_speak_day` | `speak_logs` / `speak_days` | 平迁；issues 对象归一为字符串 |
| `pet_session` / `pet_tokens` / `pet_ai_usage` | — | 跳过（无对应 / 重新登录 / 用量未迁） |

注意事项：

1. 迁移前停旧站写入，或迁后旧站只读，否则两边分叉。
2. `--plan-days` 默认 30：旧库只存做过的天，不兜底会把「做了 23 天」误判为计划完成。
3. 先 dry-run 存档统计，写入后核对；密码在各自下次登录时升级。
4. 首次迁移结果：`users=3 mastery=1289 progress=14 plans=1 speak_logs=75 speak_days=4`。
5. 迁移后若出现本地快照串号，刷新页面即可：快照键已改 `pet_sync_v2::<用户名>`，旧键归档为 `__legacy__`。

## 6. 安全约定

- 密钥只放 `deploy/.env`（仅 `PET_JWT_SECRET`）或管理页（AI Key），禁止入 git、禁止写进文档。
- `data/pet.db` 含账号信息，已 gitignore；备份文件同样不要外传。
- 站点定位内网/自用域名；TLS 在前置层终结，容器内只跑 HTTP。
- 邀请码、内网 IP、NAS 凭据记在本地凭据文件，不写进仓库。
