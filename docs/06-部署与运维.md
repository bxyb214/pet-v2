# 06 · 部署与运维

> 部署、备份、回滚、旧数据迁移的**唯一入口**。
> 开发环境统一走 Docker（macOS / Windows 相同）：`python tools/dev.py init`，Vite 5173 + uvicorn 8000 热更新；
> 生产走飞牛 NAS 的 `deploy/docker-compose.yml`，用 `tools/deploy_nas.py` 发布。
> 没有 Docker 的 Windows 机器仍可用 `tools/dev_local.py` 做发布前验证（§2.5）。
> AI Key 不走环境变量：部署后在 `/admin` 填写，存 `app_cfg` 表，接口只回尾 4 位。

## 1. 部署形态

`deploy/docker-compose.yml` 起两个容器：

| 服务 | 镜像 | 端口 | 职责 |
|---|---|---|---|
| `nginx` | `nginx:1.27-alpine` | 宿主 `8088` → 容器 `80` | 静态站 + `/api/` 反代 |
| `api` | `pet-api:<发布tag>`（默认 `latest`，`backend/Dockerfile`） | 内部 `8000` | FastAPI + Alembic 迁移 |

```text
浏览器 ──HTTP(S)──▶ 前置 TLS（路由器 / NAS 反代）──▶ nginx:8088
                                                     ├─ /           → ../frontend/dist
                                                     ├─ /media/math → 宿主课程视频（只读，Range，需登录令牌）
                                                     └─ /api/*      → api:8000
api 挂载 ../data → /app/data   （pet.db、backups/、TTS 缓存，必须持久化）
nginx 挂载 ${PET_MATH_MEDIA:-/vol2/1000/media/felix/math} → /media/math（只读）
```

- `api` 启动命令：`alembic upgrade head && python -m app.bootstrap && uvicorn ... --workers 2`。
- 空库启动时 `app.bootstrap` 写入邀请码 `CLAIM`（前端注册码统一转大写）；用该码注册的第一个账号自动成为管理员。
- nginx 直接挂载 `../frontend/dist`，**compose 不构建前端**，发布前必须先 `npm run build`。
- nginx 配置挂的是**目录** `deploy/nginx/`，改 `default.conf` 后执行
  `docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload` 即可，无需重建容器。
- 日志统一 `json-file`，单文件 10 MB × 3 份，避免 NAS 磁盘被日志占满。
- 数学视频约 5.4 GB（四年级另约 17 GB），**不进部署包**；只挂载 NAS 宿主目录。未设置 `PET_MATH_MEDIA` 时用默认路径。
- 宿主媒体目录必须对容器用户可读（nginx worker uid 101）：新上传视频后执行
  `sudo chmod -R a+rX /vol2/1000/media/felix/math`，否则 `/media/math/...` 返回 403、播放器提示加载失败。
- **视频取流需要登录**（2026-11-24 起）：`/media/math/` 挂 `auth_request /_media_auth`，
  nginx 内部子请求 `GET /api/v1/media/auth` 校验 `X-Media-Token`（来自 URL 的 `?mt=`）。
  令牌由登录态接口 `POST /api/v1/media/token` 签发，默认 6 小时（`PET_MEDIA_TOKEN_HOURS` 可改）；
  不带令牌直连返回 401。令牌必须放 URL 而不是 Cookie：iOS AirPlay 由电视端取流，带不了本站 Cookie。
  nginx 官方镜像已含 `http_auth_request_module`（`nginx -V` 可确认）。
- **静态数据缓存**：`/data/*.json`（题库、课程清单）与 `index.html` 返回 `Cache-Control: no-cache`，
  浏览器每次用 ETag 协商（未变则 304）；前端 `fetch` 也带 `cache: "no-cache"`。
  js/css/图片仍按文件名哈希缓存 30 天，换构建自动换 URL。
  换题库后用户若仍看到旧内容，先让其在站点上硬刷新一次（旧缓存条目要主动丢弃）。
- 启动时自动 `alembic upgrade head`（schema 只由迁移管理）；健康检查每 30 秒探测 `/api/v1/healthz`。
- 开发机没有 Docker 时，用 §2.5 的 `tools/dev_local.py` 在 `8088` 起原生进程，不修改生产 compose。

## 2. 本地开发环境（macOS / Windows 统一，Docker）

开发用 `deploy/docker-compose.dev.yml`：`web`（node:22 + Vite HMR，宿主机 5173）与 `api`
（python:3.12 + uvicorn `--reload`，宿主机 8000）。源码 bind mount，改前端/后端即生效；
数据库在 `data/dev/pet.db`，与生产 `data/pet.db` 完全隔离。
本机只需 Docker Desktop + Python 3.9+（仅用于跑 `tools/dev.py` 入口，构建与测试都在容器内）。

### 2.1 首次初始化

```bash
python tools/dev.py check                   # Docker / compose / 题库检查
python tools/dev.py assets --host <NAS_IP>  # 首次：从 NAS 拉题库与音频（密码走 NAS_PASS）
python tools/dev.py init                    # 构建 + alembic + bootstrap + 演示数据
# → http://localhost:5173
```

- `tools/dev.py` 会在 node_modules 命名卷为空时自动 `npm ci`，本机不需要装 Node。
  只有 `assets` 同步需要 paramiko：优先复用 `backend/.venv`，没有就 `pip install paramiko`。
- `frontend/public/data` 与 `audio` 不进 git；换题库后重跑 `assets`（`--only data|audio` 可只拉一类）。
- 空库启动自动迁移并写入 `CLAIM`；`init` 额外灌演示数据（幂等，可重复执行）。

演示账号（密码统一为 `backend/app/seed_dev.py` 的 `DEFAULT_PASSWORD`，仅 DEV 模式）：

| 账号 | 说明 |
|---|---|
| `admin` | 管理员，AI 已开通 |
| `kid` | 学生，AI 已开通 |
| `kid-free` | 学生，AI 未开通（验证 403 闸门） |

邀请码：`CLAIM`、`DEV-INVITE`。

### 2.2 日常命令

```bash
python tools/dev.py up            # 启动/重建并等待健康检查
python tools/dev.py logs api      # 或 web
python tools/dev.py seed --reset  # 清空业务数据后重灌
python tools/dev.py reset-db      # 删 data/dev/pet.db* 后重建 + 灌数
python tools/dev.py test          # 容器内 pytest + vitest（--backend-only / --frontend-only）
python tools/dev.py shell         # 进 api 容器
python tools/dev.py down          # 停容器（保留 node_modules 卷与 data/dev）
```

### 2.3 热更新与常见问题

| 现象 | 处理 |
|---|---|
| 改后端不重启 | 只监听 `backend/app/`；看 `dev.py logs api` 是否出现 `Reloading...` |
| 宿主机文件变更不生效 | `DEV_POLL=1 python tools/dev.py up`（watchfiles 轮询；macOS/Windows 挂载盘偶尔收不到 inotify） |
| 5173 / 8000 被占用 | 停掉本机原生 vite/uvicorn，或改 dev compose 的端口映射 |
| 页面空白、板块无数据 | 缺 `frontend/public/data/banks.json`，先 `dev.py assets` |
| vitest 因 localStorage 报错 | 本机 Node 不是 22。容器内测试不受影响；本机跑请切 Node 22（`.nvmrc`） |

> `vite.config.ts` 设了 `emptyOutDir: false`（dist 含 85 MB 音频）；`npm run build` 只清理
> `dist/assets`，不要手动清空 `dist/`。测试/构建统一 Node 22（`engines` 已声明）。

### 2.4 本地验证生产 compose（可选）

需要与 NAS 完全一致的 nginx 行为（SPA 回退、缓存头、媒体鉴权）时：

```bash
cd frontend && npm run build
cd ../deploy
cp .env.example .env                      # 填 PET_JWT_SECRET（openssl rand -hex 32）
mkdir -p ../data
docker compose up -d --build
curl -s http://localhost:8088/api/v1/healthz
```

浏览器打开 <http://localhost:8088>。库是 `data/pet.db`；空库用 `CLAIM` 注册第一个管理员。
8088 被占用时：macOS/Linux `lsof -nP -iTCP:8088 -sTCP:LISTEN`，Windows `netstat -ano | findstr :8088`。

### 2.5 Windows 原生环境（无 Docker，localhost:8088，仅发布前验证）

没有 Docker Desktop（或不想为开发环境装 Docker）时，用 `tools/dev_local.py` 在本机启动同一站点：
一个 uvicorn 进程同时提供 FastAPI 与 `frontend/dist`，入口固定 `http://localhost:8088`。
生产仍由 NAS 的 nginx + api 容器承担，本方式只用于开发/发布前验证。

```powershell
# 仓库根目录；先确认 Node 20+ 与 backend/.venv 可用
backend\.venv\Scripts\python.exe tools\dev_local.py --build

# 打开 http://localhost:8088
```

- `--build` 先执行 `npm run build`；之后只改后端可去掉它直接启动。前端改动需重新构建。
- 默认 `PET_DEV_MODE=1`：顶栏显示 **DEV**，AI/SOE 走模拟、不产生外部调用。
  要验证真实 AI 用 `--prod-mode`，并先在 `/admin` 配置独立 Key。
- 数据库默认 `backend/data/pet.db`（与 NAS 的 `data/pet.db` 完全隔离）；启动前自动 `alembic upgrade head`。
- 设 `PET_MATH_MEDIA=D:\path\to\math` 才会挂载 `/media/math` 并校验 `?mt=` 媒体令牌；不设时该路径返回 404。
- 需要热更新时用 §2 的 Docker 开发环境（macOS / Windows 同一套）。
- 路由/缓存行为与生产 nginx 对齐：SPA 回退，`index.html` 与 `/data/*.json` no-cache，缺失静态资源 404。

## 3. 飞牛 NAS（fnOS）

### 3.1 准备

1. 应用中心安装 **Docker**（自带 `docker compose`）。
2. 系统设置开启 **SSH**。
3. 在 NVMe 存储建目录，例如 `/vol1/1000/docker/pet-v2/`，项目与 `data/` 都放这里。
4. HTTPS：确认路由器/NAS 反代把外部 HTTPS 转到 `NAS内网IP:8088`；容器内只走 HTTP。
5. 国内拉镜像慢时，在 Docker 设置里配置镜像加速。
6. 磁盘预留 ≥2 GB（镜像 + dist 85 MB 音频 + 数据库/TTS 缓存）；时区已固定 `Asia/Shanghai`。

### 3.2 首次部署

推荐用发布脚本（本机需 Node 22；密码走 `NAS_PASS` 环境变量）：

```bash
python tools/deploy_nas.py check  --host <NAS_IP>
python tools/deploy_nas.py deploy --host <NAS_IP> --with-audio   # 首次带 85 MB 音频
```

脚本一条龙：`npm run build`（vue-tsc → 清理 `dist/assets` → vite build）→ 打包
（默认跳过 `frontend/dist/audio`）→ 上传解包（先删旧 assets，再 `chmod -R a+rX`）→
生成/保留 `deploy/.env` → 部署前 SQLite 备份 → `PET_TAG=<时间戳-sha> compose up -d --build` →
健康检查 → `latest` 打标 → 清理旧镜像。日常发布去掉 `--with-audio`（音频只需首次或新增素材时上传）。

> 词库/静态数据改动要先重新生成 `frontend/public/data/*.json`（英语词库用
> `python tools/build_data.py`）。发布脚本只做前端构建和打包，不会自动重建词库；
> 漏跑会把旧库原样复制进 `dist`。

手工部署（不推荐，仅在脚本不可用时）：

```bash
# 代码与 frontend/dist（含 audio）上传到 /vol1/1000/docker/pet-v2/
cd /vol1/1000/docker/pet-v2/deploy
cp .env.example .env && nano .env      # PET_JWT_SECRET
docker compose up -d --build
curl http://127.0.0.1:8088/api/v1/healthz
```

首次初始化：打开 `/register`，邀请码填 `CLAIM`（大小写均可，前端会转大写）——空库启动时
`app.bootstrap` 已自动写入该码，用它注册的第一个账号自动成为管理员。
随后在 `/admin` 填写 Qwen、业务空间 ID、腾讯 SOE 配置。

上线首测清单：

1. 手机/平板登录，能打开单词/阅读/听力（首次会弹麦克风权限）。
2. 口语·跟读：点「跟读评分」后腾讯 SOE 能出分。
3. 口语·对话：10 分钟提示 → 结束复盘 → 优化句可评分。
4. 造句页：AI 能判定；`/admin → 用量` 有数字。

### 3.3 NAS 特性与坑

- **docker 需要 sudo**：`admin` 不在 docker 组时，`docker info` 报
  `permission denied ... docker.sock`。`tools/deploy_nas.py` 会自动切 `sudo -S`；
  手写命令时注意 `sudo cmd1 && cmd2` 只提权 `cmd1`，要写成 `sudo sh -c "cmd1 && cmd2"`。
- **镜像加速可能 401**：`docker.fnnas.com` 对 `python:3.12-slim` 返回 401 时，先从可达源拉取再打官方标签：

  ```bash
  sudo docker pull docker.m.daocloud.io/library/python:3.12-slim
  sudo docker tag  docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim
  ```

- `backend/Dockerfile` 默认走清华 PyPI；`deploy/.env` 的 `PIP_INDEX_URL` 可覆盖。
- WebRTC / SOE 是浏览器直连第三方，**不经过 NAS**；外网必须 HTTPS（或 localhost），否则麦克风不可用。
- **Windows 打包后静态资源 403**：隔着 Windows 打的 tar，文件 mode 常为 `000`，nginx worker 无读权限。
  `tools/deploy_nas.py` 解包后自动 `chmod -R a+rX frontend/dist`；手工上传 `dist/` 时需自己补这一步。
- **数学视频 403**：宿主的 `/vol2/1000/media/felix/math` 对容器用户（uid 101）不可读。执行
  `sudo chmod -R a+rX /vol2/1000/media/felix/math` 后重试；新上传的视频同样要补这一步。
- **数学视频 401**：没带 `?mt=` 媒体令牌，或令牌已过期（默认 6 小时）。重新进入视频页会自动换新令牌；
  若页面提示「视频加载需要登录」，重新登录后再试。
- **数学视频 404**：检查 `deploy/.env` 的 `PET_MATH_MEDIA` 是否指向包含 `grade_3/`、`grade_4/` 的目录，以及
  compose 重建后 nginx 是否挂载到 `/media/math`（`docker inspect` 看 Mounts）。
- 2026-11-22 实测基线：fnOS / Debian 12，Docker 28.5.2，api ≈90 MB、nginx ≈5 MB，`/vol1/1000` 390 GB 可用。

## 4. 日常运维

### 4.1 更新

| 改动 | 操作 |
|---|---|
| 整站 | `python tools/deploy_nas.py deploy --host <IP>`（构建、上传、备份、启动、健康检查一条龙） |
| 只重建后端 | `python tools/deploy_nas.py deploy --host <IP> --skip-build`（复用现有 `frontend/dist`） |
| 只改 NAS 上已有代码 | `python tools/deploy_nas.py deploy --host <IP> --skip-upload`（不打包上传） |
| AI Key / 模型 / 单价 | 在 `/admin` 修改，无需重启 |
| nginx 配置 | `docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload` |

- 不要手工只替换 `dist/` 里的 `index.html` 或单个 `assets/*`：二者必须同一构建，否则 404。
- 发布前脚本会自动 `python -m app.maintenance backup`；alembic 迁移失败时先看 `logs api`，再回滚镜像。
- 日常查看：`python tools/deploy_nas.py ps --host <IP>` / `logs --host <IP> -n 200`。

### 4.2 备份与恢复

生产备份用 SQLite 在线备份 API（WAL 下也有**一致快照**，无需停服），备份写在
`data/backups/pet-YYYYmmdd-HHMMSS.db`，默认保留 14 份：

```bash
python tools/deploy_nas.py backup --host <NAS_IP> --download   # 立即备份并拉回 _work/backups/
python tools/deploy_nas.py backup --host <NAS_IP> --keep 30    # 覆盖保留份数

# NAS 上直接执行
cd /vol1/1000/docker/pet-v2/deploy
sudo sh backup.sh                 # 等价于 docker compose exec -T api python -m app.maintenance backup
```

- 建议 fnOS 计划任务每日跑一次 `backup.sh`；媒体目录（数学视频）可单独做文件级快照。
  计划任务用 root 运行最省事；普通用户需能免密 `sudo docker`（或加入 docker 组）。
- 部署脚本在 alembic 迁移前会自动备份一次，失败可回到上一个镜像 + 迁移前数据。

恢复（会丢备份点之后的写入）：

```bash
cd /vol1/1000/docker/pet-v2/deploy
sudo docker compose stop api
sudo cp data/backups/pet-<时间>.db data/pet.db
sudo rm -f data/pet.db-wal data/pet.db-shm     # 必须删，否则旧的 WAL 会污染新库
sudo docker compose start api
curl -s http://127.0.0.1:8088/api/v1/healthz
```

- 只迁库时不要单独拷 `pet.db`：WAL 未合并会丢最后一次写入；用备份文件或 `wal_checkpoint(TRUNCATE)`。
- **不要在容器运行时用宿主机 `sqlite3` 改库**，容易触发 `disk I/O error`；用
  `docker compose exec api python ...` 或停 api 后操作。

### 4.3 回滚

```bash
python tools/deploy_nas.py rollback --host <NAS_IP>            # 回上一个镜像 tag
python tools/deploy_nas.py rollback --host <NAS_IP> --tag <tag> # 指定 tag
```

- 发布时镜像按 `时间戳-git短sha` 打标，`latest` 跟随最近一次成功部署；脚本默认保留最近 3 个旧 tag
  （`--keep-images` 可调）。
- 回滚只切 `api` 镜像；`frontend/dist` 是 nginx 挂载的共享目录，**不会自动回退**。
  需要回滚前端时，从对应 git 版本重新 `npm run build` 再 `deploy`。
- 数据库迁移只做向前（`alembic upgrade head`）；回滚镜像不会自动降级 schema。
  若新迁移不兼容旧代码，先恢复 4.2 的迁移前备份，再回滚镜像。迁移必须可逆，
  不可逆迁移需在设计文档声明。

### 4.4 开发/测试模式

测试环境没有 AI Key 时，在 `deploy/.env` 设置：

```bash
PET_DEV_MODE=1
docker compose up -d --build api
```

- 顶栏用户名位置显示 **DEV**，用户名与头像隐藏。
- Realtime 对话 / SOE 跟读走前端模拟；`improve`、`check`、`help`、`review`、`enrich` 返回确定性结果；
  `tts` 返回提示音；`sdp` / `soe_url` 直接 503，**不发起任何外部调用**。
- 正式部署保持 `PET_DEV_MODE=0`（`.env.example` 默认值），行为与原来一致。

## 5. 旧数据迁移（一次性，已完成）

旧站 MySQL → v2 SQLite 已于 2026-11-22 执行，工具为 `tools/migrate_legacy.py`，映射规则见脚本与 git history。

- 迁移范围：active 用户、有效邀请码、掌握度、错题、阅读进度、计划、口语记录；密码保留 bcrypt，登录后自动升级 argon2。
- 迁移前停旧站写入；先 dry-run 核对统计，再加 `--execute`。
- 只迁库时用 SQLite `.backup` 做一致快照，不要单独拷 `pet.db` 或 `-wal`。
- v2 的 `PUT /sync` 是整表替换：服务端补录要等客户端 pull → merge → push 后才最终固化。

## 6. 安全约定

- 密钥只放 `deploy/.env`（仅 `PET_JWT_SECRET`）或管理页（AI Key），禁止入 git、禁止写进文档。
- `data/pet.db` 含账号信息，已 gitignore；备份文件同样不要外传。
- 站点定位内网/自用域名；TLS 在前置层终结，容器内只跑 HTTP。
- 邀请码、内网 IP、NAS 凭据记在本地凭据文件，不写进仓库。
