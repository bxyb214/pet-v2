# 会话失效守卫 — 需求

## 背景

登录信息缺失（token 被清除、过期、服务端拒绝）后，页面仍可继续跳转；
口语页因为 `perms` 为空显示「无权限」，而不是回到登录页。这会让未登录用户误以为系统仍可用。

## 用户故事

- US-01：作为使用者，登录失效后任何业务页面都应回到登录页，而不是留在页面里反复报错。
- US-02：作为使用者，重新登录后可以继续正常访问，不需要手动清缓存。
- US-03：作为维护者，服务端返回 401 时前端统一处理，不需要每个页面单独判断。

## 功能点

| 编号 | 功能 | 优先级 |
|---|---|---|
| F-01 | 除 `/login`、`/register` 外，所有路由必须有有效会话 | P0 |
| F-02 | 无 token / token 过期 / `/auth/me` 401 → 强制回登录页 | P0 |
| F-03 | 任一受保护接口返回 401 → 清会话并回登录页（去重防抖） | P0 |
| F-04 | 其他标签页清除 token 后，本页下一次导航也能感知 | P1 |
| F-05 | 登录失败仍由登录表单提示，不触发全局跳转 | P1 |

## 非目标

- 不改变登录接口、JWT 格式、权限位语义。
- 不实现 refresh token 自动续期（本期只保证失效后回登录）。

## 验收标准

- Given 未登录，When 打开 `/english/words/browse` 或 `/english/speak/talk`，Then 跳转 `/login`。
- Given 已登录，When 在 SPA 内删除 token 后点侧栏，Then 立即跳转 `/login`。
- Given token 已过期，When 刷新任意页面，Then 不渲染业务页面，直接登录页。
- Given token 被服务端判定无效，When 页面发起请求，Then 清 token 并回登录页。
- Given 登录表单输错密码，Then 停留在登录页并显示「用户名或密码错误」。

## 影响面

- 前端：`core/api.ts`、`core/token.ts`、`stores/auth.ts`、`router/index.ts`、`main.ts`。
- 后端：无改动（沿用 401）。
